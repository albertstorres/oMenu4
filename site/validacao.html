Análise Técnica: oMenu

O oMenu é uma Single Page Application (SPA), focada em acessibilidade (A11y) e performance, desenvolvida para otimizar a experiência de consulta de um cardápio digital.

1. Stack Tecnológica Completa

Componente Tecnologia Detalhe
Framework (Front)React (v18.2.0)Componentes funcionais, Hooks e Roteamento (React Router DOM).
Linguagem (Front)TypeScriptTipagem estrita (`strict: true`) para maior escalabilidade.
UI/UXRadix UI & LucidePrimitivos de acessibilidade (Radix) e ícones modernos.
ComunicaçãoAxios (v1.8.4)Cliente HTTP para consumo de API.
Backend (API)Django Rest Framework (DRF)API robusta, segura e escalável em Python.
Banco de DadosPostgreSQLBanco de dados relacional para alta integridade de dados.
Voz IA (TTS)Amazon PollyServiço de Text-to-Speech para acessibilidade.

1.5. Armazenamento de Mídia

  • Solução: Amazon Web Services (AWS) Simple Storage Service (S3).
  • Uso: O Backend do DRF gerencia os links para imagens e vídeos de produtos, armazenados de forma eficiente e acessível via S3.
  • Benefício: Desacopla o armazenamento do servidor de aplicação, garantindo alta disponibilidade, durabilidade e escalabilidade (principalmente para vídeos de demonstração de pratos).

2. Foco: Acessibilidade (A11y)

A aplicação prioriza a navegação por teclado e leitores de tela:

  • Links de Pulo (`.skip-link`): Permite navegação direta ao conteúdo principal.
  • Semântica ARIA: Uso de atributos ARIA (`aria-disabled`, `role="status"`) para clareza sobre o estado dos elementos.
  • Foco Visual: Destaque claro para navegação por teclado.

3. Estratégia de Infraestrutura e Deploy

A. CI/CD e Produção (Vercel)

  • Plataforma: Vercel (ideal para Frontend SPA).
  • Roteamento SPA: O `vercel.json` reescreve todas as rotas não estáticas para `/index.html`.
  • Performance: Uso de headers de cache agressivos (1 ano, `immutable`) para ativos estáticos.
  • Diretório: Deploy executado a partir de `frontend/`.

B. Contêineres (Docker/Nginx)

  • `Dockerfile`: Utiliza um Multi-Stage Build para gerar uma imagem final pequena e otimizada (`node:18-alpine` → `nginx:alpine`).
  • `nginx.conf`: Configurado para roteamento SPA (`try_files`), compressão Gzip e regras de cache de longo prazo.
  • `docker-compose.yml`: Orquestração local, mapeando porta `3000` do host para `80` do container.

4. Fluxo de Trabalho e DevOps

Utiliza um fluxo simplificado de branches para gerenciar ambientes:

Branch Propósito Deploy
`main`Produção (Estável)Dispara Deploy em Produção (Vercel)
`hml`Homologação/DesenvolvimentoDispara Deploy de Preview (Vercel)

Este modelo garante que as funcionalidades são testadas em `hml` antes de serem promovidas para `main`.
