Documento de Requisitos do Sistema (DRS) - oMenu

Definição dos Requisitos Funcionais, Não Funcionais e Tecnológicos.

1. Requisitos Funcionais (RF) - O que o sistema faz?

Funcionalidades do Cardápio (B2C - Usuário Final)
ID Requisito Funcional Descrição
RF.B2C.01 Acesso por QR Code O sistema deve permitir o acesso ao cardápio por meio da leitura de um QR Code na mesa.
RF.B2C.02 Leitura em Voz (TTS) O usuário deve ser capaz de ativar a leitura de qualquer item do cardápio utilizando o recurso de Text-to-Speech (TTS).
RF.B2C.03 Alto Contraste O usuário deve ter a opção de ativar o modo de Alto Contraste (texto branco em fundo preto) para facilitar a leitura.
RF.B2C.04 Filtro de Alergênicos O sistema deve permitir filtrar itens com base em alergênicos e restrições dietéticas (ex: glúten, lactose, vegano).
RF.B2C.05 Ajuste de Fonte O usuário deve poder aumentar ou diminuir o tamanho da fonte.
Funcionalidades de Gestão (B2B - Restaurante)
ID Requisito Funcional Descrição
RF.B2B.01 Cadastro de Itens O sistema deve permitir o cadastro completo de pratos e bebidas, incluindo descrição, preço, foto e lista de alergênicos.
RF.B2B.02 Gerenciamento de Mesas/QR O restaurante deve poder gerar e gerenciar QR Codes únicos para cada mesa ou área.
RF.B2B.03 Atualização em Tempo Real Alterações de preço ou disponibilidade devem ser refletidas no cardápio do usuário imediatamente.
RF.B2B.04 Relatórios de Acesso O sistema deve fornecer relatórios sobre a quantidade de acessos ao cardápio e uso dos recursos de acessibilidade.

2. Características Arquiteturais e Requisitos Não Funcionais (RNF)

Atributos de Qualidade (Não Funcionais)
ID Atributo de Qualidade Descrição
RNF.QUAL.01 Desempenho O cardápio deve ser carregado em menos de 3 segundos, mesmo em redes móveis de baixa velocidade.
RNF.QUAL.02 Usabilidade (WCAG/LBI) A interface deve seguir as diretrizes WCAG 2.1 Level AA e a Lei Brasileira de Inclusão.
RNF.QUAL.03 Disponibilidade O sistema deve ter uma disponibilidade de 99.9% (máximo de 8.7 horas de inatividade por ano).
RNF.QUAL.04 Escalabilidade A arquitetura deve suportar picos de 10.000 acessos simultâneos sem degradação do desempenho.
Requisitos Tecnológicos (Tecnologias/Infraestrutura)
ID Tecnologia/Restrição Funcional Descrição
RNF.TEC.01 Banco de Dados O sistema deve utilizar o PostgreSQL para persistência de dados.
RNF.TEC.02 Backend/API O *backend* deve ser desenvolvido em Python utilizando o Django Rest Framework.
RNF.TEC.03 Frontend/Interface O *frontend* deve ser desenvolvido em React.
RNF.TEC.04 Arquitetura de Desenvolvimento O projeto deve aderir à metodologia DevOps, com Integração Contínua (CI) e Testes Contínuos.
RNF.TEC.05 Cache O sistema deve prever a integração do Redis como camada de caching e gerenciamento de sessões, se necessário para otimização.
